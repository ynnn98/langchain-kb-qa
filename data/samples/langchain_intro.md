# LangChain 与 RAG 技术简介（示例知识库文档）

## 一、什么是 LangChain

LangChain 是一个面向大语言模型（LLM）应用开发的开源框架，最初于 2022 年 10 月发布。它的目标是让开发者能够方便地把大语言模型与外部数据源、工具和记忆结合起来，构建真正可用的智能应用。LangChain 提供 Python 和 JavaScript（TypeScript）两个主要版本的 SDK。

LangChain 的核心模块包括：

1. **模型接口（Models）**：统一封装各大模型厂商的对话模型与向量化模型（Embeddings），如 OpenAI、智谱 GLM、DeepSeek、通义千问、Ollama 本地模型等，开发者只需更换少量配置即可切换底层模型。
2. **提示词模板（Prompts）**：把系统指令、上下文、用户输入组织成可复用的模板，支持变量插值与少样本示例（few-shot examples）。
3. **检索（Retrieval）**：提供文档加载器（Document Loaders）、文本切分器（Text Splitters）、向量数据库集成（如 Chroma、FAISS、Milvus）与检索器（Retriever），是构建知识库问答的基础。
4. **链（Chains / LCEL）**：用管道符把多个组件按顺序组合成完整流程，例如"检索 -> 填充提示词 -> 调用大模型 -> 解析输出"。
5. **记忆（Memory）**：为多轮对话保存历史消息，使聊天机器人能理解上下文和指代关系。
6. **智能体（Agents）**：让大模型自主决定调用哪些工具（搜索、计算器、数据库查询等），完成更复杂的任务。

## 二、什么是 RAG（检索增强生成）

RAG（Retrieval-Augmented Generation，检索增强生成）是一种"先检索、后生成"的大模型应用架构，由 Meta（Facebook AI）研究团队在 2020 年的论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》中提出。

大模型存在两个明显缺陷：一是训练数据有截止日期，无法回答最新信息；二是对私有领域知识（企业内部文档、个人笔记等）一无所知，并且容易"一本正经地胡说八道"（幻觉问题）。RAG 的解决思路是：回答问题之前，先从一个外部知识库中检索出与问题最相关的若干段文本，把它们作为上下文放进提示词，再让大模型仅根据这些材料作答。

RAG 的标准工作流程分为两个阶段：

**入库阶段**：加载文档（PDF、Word、Markdown 等）→ 按一定长度切分成文档块（Chunk）→ 用 Embedding 模型把每个块转成高维向量 → 存入向量数据库。

**问答阶段**：把用户问题也转成向量 → 在向量数据库中做相似度检索，找出最相关的 Top-K 个文档块 → 将文档块与问题一起填入提示词模板 → 调用大模型生成最终回答。

RAG 的主要优点：知识可以随时增删而无需重新训练模型；回答有据可查，能给出引用来源，大幅降低幻觉；相比微调（Fine-tuning）成本低得多。

## 三、常见向量数据库与 Embedding 模型

**Chroma** 是一款开源的嵌入式向量数据库，安装简单（pip install chromadb）、支持持久化存储，非常适合个人项目和教学演示。其他常见选择包括 FAISS（Meta 开源的向量检索库）、Milvus（分布式向量数据库）和 Qdrant。

**Embedding 模型**负责把文本映射为语义向量，中文场景常用：智谱 embedding-3、BAAI（北京智源）的 bge 系列（如 bge-small-zh-v1.5、bge-m3）、通义的 text-embedding-v3 等。检索时使用余弦相似度或内积衡量问题与文档块的语义接近程度。

## 四、智能知识库问答的价值

基于 RAG 的知识库问答系统在企业与个人场景中都有广泛应用：企业内部规章查询、客服知识库、法律条文检索、学术论文问答、个人笔记助手等。它让用户用自然语言就能精准获取私有资料中的答案，并且每条回答都能追溯到原文出处，可信度远高于裸大模型。
